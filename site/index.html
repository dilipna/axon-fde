01 / PROBLEM FRAMING

A temperature reading is one clue.
A response needs the whole situation.

In the demonstration brief, the dispatcher works across shipment records, temperature history, signed cargo requirements and equipment information. Those sources can disagree. A recommendation needs to explain which evidence it used and what still needs a person’s judgment.

03 / HOW I HANDLED IT

The engineering decisions behind the interface.

Each decision connects an operational need to an implementation you can inspect. Expand a step for the constraint, the approach and the proof.

01Connect the existing systems safely.INTEGRATION

The need. Bring shipment context into the investigation without giving the agent unrestricted ERP access.

My approach. A SQL Server integration with read-only reporting views and SQL AST allowlisting; PostgreSQL stores application evidence, review state and audit records.

Inspect the integration architecture ↗
02Make disagreement explicit.EVIDENCE

The need. A signed cargo document and an ERP record can specify different temperature limits.

My approach. Normalize source-backed observations into typed evidence. Detect conflicts deterministically and retain the source and validity window instead of letting a model silently pick a value.

Inspect the conflicting requirements →
03Keep a human approval valid through the wait.CONTROL

The need. Conditions may change while a proposal waits for review. An old approval must not authorize a changed situation.

My approach. A checkpointed LangGraph interrupt, persisted proposal and approval, fresh-context revalidation and an idempotent executor. The public planning rehearsal is separate from this backend path.

Inspect the review and restart contracts ↗
04Verify the result, including failure.VALIDATION

The need. Executing a response does not prove that a shipment recovered.

My approach. Separate outcome verification, check freshness and recovery duration, and abstain on ambiguous sensor evidence. A frozen fault pack exposes both improvements and remaining failure modes.

What is tested separately

The authenticated backend, real database integrations, durable approval and execution safeguards. The website cannot dispatch a fleet action.

What I would validate before an operational rollout

Use authorized customer data, validate source freshness and identity, calibrate alert behavior, agree escalation rules, and measure operator decision time and intervention outcomes in a controlled pilot. These are proposed next steps, not claims of a completed rollout.
